symcc features

One chat. A whole team that builds, checks and merges.

symcc turns one Claude session into a small agent organization that works from a shared task board.

A tour of the features, with pictures. Use the arrow keys or the buttons below.

The big picture

One conversation, a whole team

You talk to one lead. Everyone else does one narrow job.

The one who writes a change is never the one who checks it. Scouts cannot change your project by themselves.

Files

Each task has a file list. A worker may only change those files.

after

A task can wait for others to be merged first.

Order

Among free tasks, the lowest order starts first, then the lower task number.

Feature 3

Workers in parallel

Up to 3 workers run at once (max_parallel). Each has its own folder and branch. Merges go one by one. The times below are only a picture.

One merge queue for the whole project. Only the front task catches up, runs tests and merges, so the tested code is exactly the merged code.

Feature 4

Sandboxed worktrees

Each task works in .symcc/worktrees/T-n on branch symcc/T-n. Your own branch stays untouched until a merge.

The checked merge

  1. Bring the task up to date with the branch.
  2. Scope check against the task's files.
  3. Run your test commands.
  4. Only then move the branch.

Work is kept on failure

A failed or stopped task keeps its folder and branch. A retry continues from there.

An honest limit

The guards read command text and stop honest mistakes. They are not a security boundary.

Feature 5

The line: one straight road for every change

The exits on the side are where a person or a retry takes over.

Prep

symcc commits, leaves out secret-looking files (.env, *.pem, ...) and checks every changed file is on the task's list.

Queue

One merge queue, oldest first.

Merge

Only now does your branch move forward. Your uncommitted work in other files is never overwritten.

Feature 5, the map

Nine statuses and who moves a task

Needs you means the next move is yours: the task is in review, waiting or failed, or a worker asked for more time.

Feature 6

The checker: a fresh agent tries to break it

Off by default, because it costs time and tokens. It did not write the change, so it looks with fresh eyes.

It can

Read the task and the whole diff, and try the change for real with small probe scripts.

It cannot

Edit the project's files, change git, or run your tests (they run once, in the queue).

Skipped for

Investigations and docs-only changes.

Feature 7

Scouts: they look for work while you are away

Read-only agents. They run on a timer or on demand with /symcc-scout <name>.

bug a slip in the date code
test gap a file with no tests
board a task that looks stuck

Also: old dependencies and security notices.

finding→lead decides→todo or backlog

The scout_findings setting picks auto (to do) or backlog (waits for you). Scouts cannot edit files or create tasks themselves.

Feature 8

Roles and kinds: two decks of cards

Role = who does it

generaldocsrefactorresearchersecuritytesteryour own

A role is one Markdown file. Its checklist goes into the worker's prompt. It can also pick a model. general is the default.

Kind = what the task is

changebugfeaturerefactordocsinvestigationyour own

A kind is a label. It changes how a task runs in only two cases:

Investigation

The result is an answer, not a change. It never merges, and the task waits for you, even in auto mode.

Docs-only change

Skips the checker and is never flagged for having no tests.

Feature 10

Organizational memory

.symcc/org-mem.md holds short notes. Every new worker, checker and scout gets them in its prompt.

One task's trap (a slow test, a refused command) saves time on every later task. Agents only suggest. The lead decides, so the file stays short and free of repeats.

Feature 13

A board that keeps itself in order

symcc checks the board after every change and every two minutes. A healthy board sends nothing.

Triage looks for

Stuck waits on a dropped or failed task, or a loop
Starving an older task pushed back again and again
Too serial a chain that shares no files
Too long needs you for over an hour

Tidy-up

Archive done and dropped tasks move off the board after 14 days (archive_days)
/symcc-doctor lists old backups, branches and folders with sizes. Changes nothing until you say fix
Small files finished tasks keep only a short stub in board.json

A few ideas

Toward autonomous agent organizations

symcc is practical today. Here is where the idea could go.

It learns

Org-mem already keeps lessons across tasks.

It adapts

Triage is a small, rule-based version of the loop above. A smarter controller is an open question.

It is measured

By verified progress (changes that passed the checks and merged), not by commits or tokens.

A few ideas

Structure matters

Research on agent teams points the same way.

Parallel work

Coordination helps.

Sequential work

Coordination can hurt.

Much apparent agent productivity is organizational waste, such as clashing edits. This is why symcc isolates work in worktrees, orders tasks with after and counts a task only when it is merged.

Closing

Ask for it in chat. Let the team build it.

See it

One board in the terminal, VS Code or OpenCode.

Trust it

Own folders, a checker, tests and a checked merge.

Steer it

Modes, questions and review keep you in charge.
