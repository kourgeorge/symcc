symcc is an agent organization inside your coding agent: you say what you want, workers build it in parallel, and nothing merges until a checker and your tests are happy.

How it works

    
    
      
  1. You say itType an idea, a bug or a wish into your normal chat, at any time.
    2. 
      
  2. The lead plans itIt turns your words into tasks, sets their order, and asks you only for real decisions.
    3. 
      
  3. Workers build itEach task gets its own worker, folder and branch. Several run at once.
    4. 
      
  4. A checker tries to break itAn optional second agent reads the change and sends it back if it finds problems.
    5. 
      
  5. Your tests decideThe merge queue runs your tests on each change, one at a time, then merges it.
    6.

        ◉The Live tabSee each task's way to main, as it happens.
        
Every running task is a lane on the path that task really takes: work, check, queue, tests, merged (an investigation only work and answer; a task that needs your review has a "you" station before merged; a docs-only change shows check as skipped). You see the time at each station, the tokens of the whole task so far (every try) and how many times the usual (median) task that is, the task's own working time, how its tokens split between the worker and the checker, and how often the checker sent it back. While something waits for you (a question, a task to review), a NEEDS YOU section at the top lists it, one warning row each.

        ╰─○A folder per workerWorkers can't step on each other.
        
Each worker gets its own copy of the project on its own branch. Your branch stays untouched until merge. Each task lists the files it may change, so a stray edit is refused instead of hiding in the diff.

        
main   ●───●───●───●
           │   ╰─────○ T-740  +1 commit · 3 behind
           ╰─────────○ T-747  not started

      

      

        ↺A checkerA second agent tries to break each change.
        
Before the tests run, the checker reads the change and the task. If it finds problems, the task goes back to a worker with the checker's words, and a new try starts. You see each try on the task page.

        
try 1 → the checker found problems
try 2: worker started

      

      

        ✓A merge queueThe code that was tested is the code that merges.
        
Finished changes take turns. Each one is brought up to date with main, your test commands run on it, and only then does it merge. In approve merge mode you look at the diff first.

        
T-747 try 1 → checks passed
T-747 try 1 → merged into main
♪ symcc: T-747 done

      

      

        ◇ScoutsAgents that only look, on a timer.
        
Scouts look for bugs, gaps, missing tests and copied code while you are away. They never change your project. They report to the lead, and the lead makes a task of what is worth doing.

        
◇ scout gaps-bot found: Checker send-backs,
  the most common failure, are left out of the
  failed-tries reasons and total → T-736

      

      

        ▍Organizational memoryWhat one agent learns, the next one knows.
        
Agents suggest short notes about the project: a trick for the tests, a command the guard refuses. The lead keeps the surprising ones, and every new worker gets them with its task.

        
11-21  tests   In tests, put dates relative
               to now, never a fixed date

      

      

        ▤A board that staysA plain file, kept after the chat ends.
        
The board lives in your project. Close the chat, come back tomorrow: the tasks, their history, tries, time and cost are all still there.

Why not just run agents in parallel?

    
You can open five agent chats at once. The hard part is everything around them. Here is what changes with symcc.

    

      

        
Agents in parallel, by handsymcc

        
          
Where you talkOne chat per agent; you hop between themOne lead; it hands out the work

          
Keeping trackIn your head, or a notes fileA board with every task, its why and its history

          
Edits clashingAgents share one folder and overwrite each otherEach worker has its own folder and branch

          
Stray changesFound later in the diff, if at allRefused: each task lists the files it may change

          
Checking the workYou read every changeA checker tries to break it, then your tests run

          
MergingBy hand, with conflictsA queue merges one tested change at a time

          
Finding more workOnly what you noticeScouts look while you are away

        
      

    

  


  

    
Install

    
Claude Code

    
You need Claude Code and git. There is no build step.

    
claude plugin install symcc --marketplace kourgeorge/symcc

    
Then start Claude Code in your project. The board opens by itself; if not, run /symcc.

    
OpenCode

    
symcc also runs in OpenCode 2.3 or newer (a first version). From a clone of symcc:

    
git clone https://github.com/kourgeorge/symcc && sh symcc/scripts/install-opencode.sh

    
Or, with no clone:

    
opencode plugin add github:kourgeorge/symcc

    
Pick one of the two ways. The details are in the guide.

  


  

    
Questions

    

      Does symcc change my branch while I work?
      
No. Workers build in their own folders and branches. Your branch only changes when the merge queue merges a change that passed your tests.

    

    

      Do I have to watch it?
      
No. In auto merge mode, tested changes merge by themselves and symcc can say "T-747 done" out loud. In approve merge mode, each change waits for you to look at it first.

    

    

      What does it cost?
      
symcc is free. The agents use your normal Claude Code or OpenCode account, so each try costs tokens. The task page shows the time, tokens and cost of every try, and you choose how many agents run at once.

    

    

      Is it safe to let agents merge?
      
Nothing merges until your tests pass, and each task may change only its listed files. These checks catch honest mistakes; they are not a security boundary. The guide explains why each part is there.

    

    

      Is the demo above real?
      
Yes. It is symcc building symcc: the task numbers, titles and steps come from its own board and history. It is drawn with HTML so you can read it, pause it and switch views.
